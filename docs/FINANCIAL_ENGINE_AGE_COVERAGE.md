# F01–F18 age and effective-date coverage

**Atlas implementation addendum — 5 November 2026.** This is a delivery and test specification for the [18 approved financial-engine contracts](../research/retirepilot_2026_11_04/financial_engine_contracts_18.json), not a claim that all engines are implemented or financially validated. The v2.7 repository contains bounded references and a synthetic projection; the full F01–F18 ledger remains future work. External pilot: **NO-GO**.

## Common rule for every engine

Store the subject person ID, date of birth, calculation/as-of date, event or transaction date, rule effective interval, source and evidence date. Evaluate age for **that person at the rule's specified date**, rather than using one household age or the age at onboarding. Preserve unknown, withheld and unsupported facts as distinct states; none may silently become zero. Keep each adult's records and consent separate. A statutory rule must carry its published source and version; an unpublished future rate is a labelled assumption, never an official rate.

“Birthday boundary” below means the required before/on/after check. Some rules take effect on the exact birthday, some in the following month, and some use age at 1 January of a work year. Do not apply one convention to all engines. Leap-day dates require a documented official or legal convention before an engine treats a substituted birthday as verified.

## Acceptance and test evidence

1. For each implemented age rule, create an independent numerical oracle from the cited, effective-dated source. Test the preceding period, trigger period and following period. For exact-day events, test day before, birthday and day after. Include year-boundary, leap-day and missing-DOB cases when the official convention is established.
2. Test each adult separately. A spouse's birthday, CPF balance or benefit status must not alter another adult's rule. Refuse unknown consent, PR cohort, opt-in, official payout estimate and eligibility instead of imputing a value.
3. Add source version, effective dates, input provenance and output limitations to every calculation result. Assert balance conservation, gross/net separation and no cash/CPF double count.
4. Mark **specified**, **implemented**, **internally tested**, **independently verified** and **blocked** separately in the F01–F18 and S001–S046 coverage register. A test of a refusal or preview does not mark a full engine implemented.
5. The current [age-boundary regression tests](../tests/test_age_boundaries.py) cover only existing employee CPF, platform CPF, 2026 SEP MediSave and age-55 snapshot reference paths. No test in this repository certifies all 18 engines or a real-person financial result.
